# Исследование: edtfind, v8find, совместимость хранилища, выбор версий

**Дата исследования:** 2026-09-09. Источники: клоны в temp: `edtfind` (oscript-library, main=1.0.2), `edtfind2` (portalyug, =2.0.2), `v8find`, v8runner, gitsync.

## 0. Ключевая находка про версии библиотек

- `gitsync-plugins` 2.0.3 требует **`edtfind` 2.0.2**. Репозиторий `oscript-library/edtfind` на GitHub содержит только **1.0.2** со старым API (строка-путь). Версия 2.x живёт в форке **`github.com/portalyug/edtfind`** (теги v2.0.0–v2.0.2) — именно она ставится через opm и возвращает структуру с `ПутьКcli`.
- Класс `Платформа1С` — это **НЕ часть gitsync**, а библиотека **`v8find`** (в `useIbcmd.os`: `#Использовать v8find`).

## 1. edtfind 2.0.2 — поиск EDT (`src/Классы/ПоискEDT.os`)

`НайтиИнформациюОEDT(ВерсияEDT = "")` возвращает **Структуру**: `КаталогEDT`, `ВерсияEDT`, `ПутьКcli` (пустая строка, если не найден).

**Каталоги сканирования (Linux):** `$HOME/.local/share/1C/1cedtstart/installations` и **`/opt/1C/1CE/components`**.

**Маркер обнаружения:** рекурсивно ищутся файлы `1cedt` и `1cedt.ini` (НЕ `1cedtcli`!). Если в образе только `1cedtcli` без `1cedt`/`1cedt.ini` — установка НЕ обнаруживается.

**Извлечение версии:** от маркера вверх по каталогам, regex `1c[-_ ]edt[-_ ](\d+\.\d+(\.\d+)*)`; `YYYY.M` → `YYYY.M.0`. Т.е. `1c-edt-2024.2.3+54-x86_64` → `2024.2.3`.

**Формат параметра `GITSYNC_EDT_VERSION`:** `^\d+\.\d+(\.\d+)*$` — `2024.2.3`, `2026.2`, даже `2024.1.2.3`. Пустая строка → максимальная версия.

**Выбор версии:** 1) точное совпадение; 2) если одна точка (`2026.2`) — первая (старшая) версия с префиксом (ВНИМАНИЕ: чистый строковый префикс — `2026.2` матчится и на `2026.20.x`); 3) иначе исключение со списком доступных версий.

**ПутьКcli:** `1cedtcli` должен лежать **непосредственно в КаталогEDT**.

**ring:** edtfind сам ring не использует. Fallback в edtExport: если `ПутьКcli` пуст — рекурсивный поиск `ring` в `/opt/1C/1CE/components`, команда `ring edt@<версия>:x86_64 workspace import ...`.

→ **В образе:** EDT класть в `/opt/1C/1CE/components/1c-edt-<версия>-x86_64/` с файлами `1cedt` (или `1cedt.ini`) и `1cedtcli` в корне каталога. `GITSYNC_EDT_VERSION=2026.2.0` (точная) или `2026.2` (префикс). Ring не нужен.

## 2. v8find — `Платформа1С.ПутьКIBCMD` / поиск платформы

Файл: `v8find/src/Классы/Платформа1С.os` (0.3.2).

**Трактовка маски версии:** 1 компонент (`8`) → максимум из всех; 2 (`8.3`) → фильтр по платформе; 3 (`8.3.27`) → по релизу; 4 → точная версия. Сортировка по убыванию.

**Стандартные пути Linux:**
- `/opt/1C/v8.*/i386` и `/opt/1C/v8.*/x86_64` — версия определяется запуском `rac -v`;
- `/opt/1cv8/i386`, `/opt/1cv8/x86_64` — сканируются подкаталоги по маске **`8.?.*.*`**;
- `/opt/1cv8` — тоже сканируется по `8.?.*.*`.

Исполняемые файлы ищутся **прямо в каталоге версии** (без `bin/`): `1cv8`, `1cv8t`, `1cv8c`, `rac`, `dbgs`, `ibsrv`, `ibcmd`. Каталог засчитывается как версия при наличии хотя бы одного.

**Симлинк `/opt/1cv8/current` НЕ работает** (имя не матчится на `8.?.*.*`). Рабочая альтернатива — `/opt/1C/v8.3` (даже симлинк): версия определится через `rac -v`.

→ **В образе:** платформу класть в `/opt/1cv8/x86_64/8.3.27.2325/` (с `1cv8`, `rac`, `ibcmd` внутри). `GITSYNC_V8VERSION=8.3` найдёт максимальную; `ibcmd` берётся из того же каталога.

## 3. v8runner

Поиск платформы полностью делегирован в v8find. При инициализации — маска `8`, предпочтение x64. `--v8-path` в gitsync задаёт прямой путь и обходит поиск.

## 4. Совместимость формата хранилища

- **Файл `ver` хранилища нигде в gitsync/v8storage не читается.** Проверки «платформа ≥ версия хранилища» в коде нет.
- gitsync оперирует только **порядковым номером версии** (файл VERSION в WORKDIR).
- Совместимость формата хранилища **полностью отдана платформе 1С**: если платформа контейнера младше версии, записанной в `ver` (у нас: `8.3.27.2325`), `1cv8` вернёт ошибку несовместимости — внятной предварительной диагностики нет (добавим проверку в `doctor`).
- Единственный feature-gate: опции отчёта для платформы ≥ 8.3.17 (`-IncludeCommentLinesWithDoubleSlash`).

→ **Требование:** платформа в контейнере **≥ 8.3.27.2325** (линейка 8.3.27, как указал пользователь). При выходе нового релиза хранилища (например перешли на 8.3.27.2400) контейнер надо пересобрать с платформой не младше этой.

## Практические выводы для образа

1. EDT → `/opt/1C/1CE/components/1c-edt-<версия>-x86_64/` (+`1cedt`/`1cedt.ini`, `1cedtcli`).
2. Платформа → `/opt/1cv8/x86_64/<версия>/` (+`1cv8`, `rac`, `ibcmd`).
3. `GITSYNC_V8VERSION=8.3` или точнее; `GITSYNC_EDT_VERSION=2026.2.0`.
4. В `doctor` добавить сравнение версии платформы контейнера с версией из `ver` хранилища.
